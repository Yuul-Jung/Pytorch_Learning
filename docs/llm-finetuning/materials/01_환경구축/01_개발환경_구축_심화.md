# 2. 파인튜닝 환경이 중요한 이유

## 2-1. 프로그램 설치와 학습 성공은 다르다

생성형 AI 모델 학습에는 일반적인 Python 실행보다 많은 요소가 관여한다. 같은 코드라도 **GPU 드라이버, PyTorch 빌드, 패키지 의존성, 모델 접근 권한, 데이터 형식**에 따라 실행 가능 여부가 달라진다.

- Python 코드 문법 검사 통과: 파이썬이 코드를 읽을 수 있다는 뜻이다.
- 라이브러리 `import` 성공: 모듈이 설치되었고 최소한의 로딩이 가능하다는 뜻이다.
- `torch.cuda.is_available()` 참: PyTorch에서 CUDA 장치를 사용할 수 있다는 뜻이다.
- 모델 다운로드·추론 성공: 모델 형식과 메모리 조건을 통과했다는 뜻이다.
- 실제 학습 한 단계 성공: 순전파·손실 계산·역전파·가중치 갱신이 수행됐다는 뜻이다.

**앞 단계가 성공해도 뒤 단계의 성공을 자동으로 보장하지 않는다.**

## 2-2. 환경의 다섯 계층

| 계층 | 구성 요소 | 발생 가능한 문제 |
|---|---|---|
| 운영체제 | Ubuntu, 파일 권한, 네트워크 | 저장공간 부족·권한 오류 |
| 연산장치 | NVIDIA GPU, 드라이버 | 드라이버 미탐지·VRAM 부족 |
| 언어환경 | Python 3.11, `.venv`, pip | 파이썬 버전 충돌 |
| 학습도구 | PyTorch, transformers, trl, peft | 라이브러리 버전 불일치 |
| 실습자원 | 모델, 데이터셋, 결과 폴더 | 인증·형식·경로 오류 |

## 2-3. 실습 전 확인 질문

2. 설치한 라이브러리가 현재 가상환경에 들어 있는가?

4. 실습용 모델과 데이터가 저장될 공간이 있는가?

**판정 원칙:** 모르는 값은 추측해서 기입하지 않고 실제 명령의 출력으로 확인한다.

# 3. 핵심 개념: LLM 학습에 쓰이는 메모리

## 3-1. 용어 연결

- **LLM(Large Language Model, 라지 랭귀지 모델·대규모 언어 모델)**: 대량의 텍스트를 학습해 토큰의 관계를 추론하는 모델이다.
- **Fine-Tuning(파인튜닝·추가 학습)**: 사전학습된 모델을 목적 데이터로 다시 조정하는 학습 방법이다.
- **GPU(Graphics Processing Unit, 지피유·병렬 연산 장치)**: 행렬·벡터 계산을 병렬로 처리한다.
- **VRAM(Video RAM, 브이램·GPU 전용 메모리)**: GPU가 모델 가중치와 학습 계산 결과를 저장하는 공간이다.
- **CUDA(쿠다·엔비디아 GPU 병렬연산 플랫폼)**: CUDA 대응 GPU를 PyTorch에서 활용하는 연산 기반이다.

## 3-2. 왜 추론보다 학습이 무거울까?

추론은 일반적으로 입력을 받아 다음 토큰을 생성한다. 학습은 예측과 정답의 차이인 **손실(Loss, 로스·오차 값)**을 계산하고, 역전파로 미분값을 구한 뒤, 학습 가능한 매개변수를 갱신한다.

```text
[추론]
입력 토큰 → 모델 가중치 → 출력 토큰

[학습]
입력 토큰 → 모델 가중치 → 예측
                          ↓
정답 토큰 ───────────→ 손실 계산
                          ↓
                    역전파/기울기
                          ↓
                    매개변수 갱신
```

## 3-3. GPU 메모리를 구성하는 요소

| 요소 | 설명 | 일반적 증가 요인 |
|---|---|---|
| 모델 가중치 | 사전학습 매개변수 | 모델 규모, 저장 비트 수 |
| 활성값 | 계층 중간 계산 결과 | 배치 크기, 시퀀스 길이 |
| 기울기 | 학습 대상 매개변수의 미분값 | 학습 대상 가중치 수 |
| 옵티마이저 상태 | 가중치 갱신에 쓰이는 중간값 | 옵티마이저 유형 |

**LoRA(로라·저랭크 적응)**는 학습 대상 매개변수를 줄이고, **QLoRA(큐로라·양자화 기반 로라)**는 보통 기반 모델을 저비트로 적재해 메모리 요구량을 줄이는 방향이다. 두 기술의 원리는 4~5차시에서 자세히 다룬다.

## 4-2. 폴더 구조

```text

├── data/                # train.jsonl, eval.jsonl
├── models/              # 원본 모델·LoRA 가중치
```

- `data/`에는 개인정보·라이선스 제한·비공개 데이터가 없는지 검토한다.
- API 토큰이 필요한 경우 코드에 직접 넣거나 화면 캡처로 공개하지 않는다.

# 5. Ubuntu 사전 점검과 Python 준비

## 5-1. 시스템 상태 확인

터미널에서 아래 명령을 **한 줄씩** 실행한다. 결과의 실제 값은 장비마다 다르다.

```bash
# 운영체제 이름과 배포판 버전 확인
lsb_release -a

# 실제 Python 3.11 설치 여부 확인
python3.11 --version

# 저장공간 사용량과 여유 용량 확인
df -h .

# 메모리 총량과 사용량 확인
free -h

# NVIDIA GPU 및 드라이버 표시 (미설치 시 오류 가능)
nvidia-smi
```

## 5-2. 명령별 해석

- `lsb_release -a`: 현재 운영체제와 버전을 표시한다. 명령 미설치 시 `cat /etc/os-release`를 사용한다.
- `python3.11 --version`: `Python 3.11.x` 형태인지 확인한다. 출력이 없으면 별도 Python 설치 절차가 필요하다.
- `df -h .`: 현재 폴더가 위치한 파티션의 남은 공간을 확인한다.
- `free -h`: 시스템 RAM 사용량을 확인한다. VRAM 확인 명령과 혼동하지 않는다.
- `nvidia-smi`: 드라이버가 보고하는 GPU 종류·상태·메모리 사용량을 확인한다.

## 5-3. 가상환경 준비에 필요한 기본 도구

```bash
# 패키지 목록 갱신 (시스템에 연결된 저장소 조회)
```

# 6. 프로젝트와 `.venv` 생성

## 6-1. 작업 위치와 독립 가상환경

```bash
# 강의 실습용 프로젝트 폴더 생성 및 이동
mkdir -p ~/lab_llm
cd ~/lab_llm

# Python 3.11용 가상환경을 .venv 폴더에 생성
python3.11 -m venv .venv

# 현재 터미널에 가상환경 활성화
source .venv/bin/activate

# 실행 중인 Python 위치·버전 확인
which python
python --version

# pip 설치 도구 갱신
python -m pip install --upgrade pip
```

### 핵심 해설

`python3.11 -m venv .venv`는 시스템 Python을 제거하거나 변경하지 않고 **프로젝트 전용 패키지 공간**을 생성한다. `source`는 현재 셸의 환경변수를 변경해 이 가상환경의 `python`을 우선 사용하게 한다.

## 6-2. 활성화 확인

```bash
# 프로젝트의 .venv 안에 python이 있는지 확인
which python

# pip도 동일한 Python에 묶여 있는지 확인
python -m pip --version

# 작업 종료 시 가상환경 비활성화
deactivate
```

출력 경로에 `lab_llm/.venv/bin/python`이 포함되면 활성화 상태를 확인할 수 있다. `deactivate` 이후 다시 실습하려면 `source .venv/bin/activate`를 실행한다.

## 6-3. VS Code와 연동

1. `code ~/lab_llm`로 프로젝트 폴더를 연다.
2. Python 확장이 설치되어 있다면 명령 팔레트에서 **Python: Select Interpreter**를 선택한다.
3. `~/lab_llm/.venv/bin/python`을 인터프리터로 지정한다.
4. 터미널과 VS Code의 선택한 인터프리터가 같은 경로인지 확인한다.

**주의:** GUI 편집기에서 실행하는 Python과 터미널의 Python이 서로 달라지는 문제를 피한다.

# 7. PyTorch와 Hugging Face 도구 설치

## 7-1. PyTorch 먼저 설치

PyTorch(파이토치·딥러닝 연산 프레임워크)는 **운영체제·패키지 도구·연산 플랫폼(CPU/CUDA)**에 맞는 공식 설치 명령을 선택한다.

공식 설치 선택기: https://pytorch.org/get-started/locally/

1. OS에 **Linux**, Package에 **Pip**, Language에 **Python**을 선택한다.
2. GPU 환경이면 실제 드라이버에 적합한 CUDA 빌드를 선택한다.
3. 표시된 공식 설치 명령을 **활성화된 `.venv`** 터미널에서 실행한다.
4. 이후 `python -c "import torch; print(torch.__version__)"`로 로딩을 확인한다.

**중요:** 드라이버에 나타나는 CUDA 버전은 드라이버가 지원하는 기능 범위에 관한 정보이며, PyTorch 패키지가 실제로 사용하는 CUDA 런타임과 반드시 같지는 않다. 설치 명령을 추측해서 고정하지 않는다.

## 7-2. 학습도구 설치

```bash
# 가상환경 내부에서 실행: Hugging Face 관련 패키지
python -m pip install -U transformers datasets accelerate

# SFTTrainer(지도 파인튜닝 학습기)와 PEFT 설치
python -m pip install -U trl peft safetensors

# QLoRA 준비: 환경에 따라 지원 조건 확인 필요
python -m pip install -U bitsandbytes

# 핵심 모듈을 Python에서 찾을 수 있는지 검사
python -c "import torch, transformers, trl, peft; print('IMPORT_OK')"
```

### 패키지 역할

| 패키지 | 기능 |
|---|---|
| `torch` | 텐서 연산, 역전파, GPU 활용 |
| `transformers` | 모델·토크나이저 적재, 생성 |
| `datasets` | 학습 데이터의 로딩·처리 |
| `accelerate` | 장치 배치·학습 실행 지원 |
| `trl` | `SFTTrainer` 제공 |
| `peft` | LoRA와 같은 효율적 학습 기법 제공 |
| `safetensors` | 모델 텐서 저장 형식 지원 |
| `bitsandbytes` | 저비트 양자화 연산 기능 |

**검증 수준:** `IMPORT_OK`만으로 GPU 학습 성공이 확인되는 것은 아니다.

# 8. 핵심 코드: 환경을 측정하는 `check_env.py`

이 개선판에 **독립 실습 파일 `check_env.py`를 동봉**했다. 아래 코드는 해당 파일과 일치한다.

```python
"""01차시: Python/PyTorch/CUDA 환경과 실습 가능 여부를 확인합니다."""
import importlib.metadata as md
import platform

print('Python:', platform.python_version())
for name in ('torch', 'transformers', 'trl', 'peft', 'datasets', 'accelerate', 'bitsandbytes'):
    try:
        print(f'{name}: {md.version(name)}')
    except md.PackageNotFoundError:
        print(f'{name}: 미설치')

try:
    import torch
    print('CUDA 사용 가능:', torch.cuda.is_available())
    if torch.cuda.is_available():
        print('GPU:', torch.cuda.get_device_name(0))
        print('총 VRAM(GiB):', round(torch.cuda.get_device_properties(0).total_memory / 2**30, 2))
        print('BF16 지원:', torch.cuda.is_bf16_supported())
except ImportError:
    print('PyTorch 미설치')
```

## 8-1. 코드 풀이 — 이 코드가 무엇을 하는가

- `importlib.metadata.version(name)`: 설치된 **배포 패키지 버전**을 문자열로 읽는다. 해당 패키지가 없으면 예외가 발생한다.
- `try` / `except`: 한 패키지가 없어도 전체 점검을 중지하지 않도록 한다.
- `torch.cuda.is_available()`: PyTorch의 CUDA 사용 가능 여부를 참/거짓으로 표시한다.
- `get_device_name(0)`: PyTorch가 인식한 첫 번째 CUDA GPU의 장치 이름을 표시한다.
- `total_memory / 2**30`: 첫 번째 GPU의 전체 전용 메모리 용량을 GiB 단위 수치로 환산한다. 출력은 정확하게 **GiB** 단위로 표시한다.
- `is_bf16_supported()`: 해당 환경에서 BF16 연산 지원 가능 여부를 조회한다.

## 8-2. 실행

```bash
# 01_환경구축 폴더에서 실행
python check_env.py
```

예시 출력(`CUDA 사용 가능: True`)은 형식 설명일 뿐, 사용자 GPU의 실측 결과를 대신하지 않는다.
